Adicionar Fato¶

Guia para criar uma nova tabela de fato no modelo dimensional.

Tipos de Fato¶

Tipo Grão Quando usar Exemplo no projeto
Transacional 1 evento = 1 linha Registros individuais fct_court_case, fct_notificacao_violencia
Periódico (snapshot) Período × Entidade Dados pré-agregados fct_crime_mensal, fct_indicador_justica

1. Criar o Modelo SQL¶

Crie em dbt_project/models/marts/violence/ (transacional) ou dbt_project/models/marts/aggregate/ (periódico).

Fato transacional¶

-- dbt_project/models/marts/violence/fct_nova.sql

with staging as (
    select * from {{ ref('stg_nova_fonte__tabela') }}
),

-- Joins com dimensões
final as (
    select
        -- Chave substituta
        {{ dbt_utils.generate_surrogate_key(['record_id']) }} as nova_sk,

        -- Chave natural (degenerada)
        s.record_id,

        -- Foreign keys para dimensões
        dd.date_sk as event_date_sk,
        dl.location_sk as location_sk,
        coalesce(dvp.victim_profile_sk, 'unknown') as victim_profile_sk,

        -- Métricas e atributos
        s.valor,
        s.quantidade

    from staging s

    -- Join com dim_date
    left join {{ ref('dim_date') }} dd
        on s.event_date = dd.full_date

    -- Join com dim_location (por nome normalizado)
    left join {{ ref('dim_location') }} dl
        on s.municipio_normalizado = dl.municipality_name_normalized

    -- Join com dim_victim_profile
    left join {{ ref('dim_victim_profile') }} dvp
        on {{ map_faixa_etaria('s.idade') }} = dvp.age_range_code
        and s.sexo_code = dvp.sex_code
        and s.raca_code = dvp.race_code
)

select * from final

Fato periódico¶

-- dbt_project/models/marts/aggregate/fct_nova_mensal.sql

with staging as (
    select * from {{ ref('stg_nova_fonte__tabela') }}
),

-- Pré-agregar no grão desejado
aggregated as (
    select
        reference_date,
        municipio,
        categoria,
        sum(quantidade) as total_quantidade,
        count(*) as total_registros
    from staging
    group by 1, 2, 3
),

final as (
    select
        {{ dbt_utils.generate_surrogate_key(
            ['reference_date', 'municipio', 'categoria']
        ) }} as nova_mensal_sk,

        dd.date_sk as reference_date_sk,
        dl.location_sk,

        a.categoria,
        a.total_quantidade,
        a.total_registros

    from aggregated a

    left join {{ ref('dim_date') }} dd
        on a.reference_date = dd.full_date

    left join {{ ref('dim_location') }} dl
        on upper(a.municipio) = dl.municipality_name_normalized
)

select * from final

2. Criar Bridge (se necessário)¶

Se o fato tem relacionamentos N:N, crie uma tabela bridge.

Via unpivot de booleans¶

-- dbt_project/models/marts/aggregate/bridge_nova_tipo.sql

with fact as (
    select nova_sk, has_tipo_a, has_tipo_b, has_tipo_c
    from {{ ref('fct_nova') }}
)

select nova_sk, 'tipo_a' as tipo
from fact where has_tipo_a = true

union all

select nova_sk, 'tipo_b' as tipo
from fact where has_tipo_b = true

union all

select nova_sk, 'tipo_c' as tipo
from fact where has_tipo_c = true

Via parsing de JSON¶

-- Similar ao bridge_case_crime_type
select distinct
    nova_sk,
    (regexp_matches(campo_json, '"codigo":\s*(\d+)', 'g'))[1]::int as codigo
from {{ ref('fct_nova') }}
where campo_json is not null

3. Documentar no Schema YAML¶

Adicione em dbt_project/models/marts/_marts.yml:

models:
  - name: fct_nova
    description: >
      Tabela de fato para novos registros.
      Grão: 1 por registro.
    columns:
      - name: nova_sk
        description: Chave substituta.
        tests:
          - unique
          - not_null
      - name: event_date_sk
        description: FK para dim_date.
        tests:
          - relationships:
              arguments:
                to: ref('dim_date')
                field: date_sk

4. Testar¶

# Rodar o novo modelo e suas dependências
./scripts/dbt-run.sh +fct_nova

# Testar
./scripts/dbt-test.sh

Checklist¶

  • Modelo staging existe e está testado
  • Modelo de fato criado na pasta correta (violence/ ou aggregate/)
  • Chave substituta via generate_surrogate_key()
  • Joins com dimensões relevantes (dim_date no mínimo)
  • Bridge table criada (se houver relações N:N)
  • Schema YAML com testes unique, not_null e relationships
  • dbt run e dbt test passam
