Neon (Produção)¶

O banco de produção é um Neon PostgreSQL serverless na região sa-east-1 (São Paulo). O Docker local serve para desenvolvimento e testes; os dados reais ficam no Neon.

Credenciais¶

O projeto tem dois usuários no Neon:

Usuário Permissão Uso
neondb_owner Leitura e escrita Pipeline (ingestão + dbt)
powerbi_reader Somente leitura Power BI, Metabase, Tableau

Para obter as credenciais, entre em contato com o administrador do projeto.

Nunca commitar credenciais

As senhas ficam no .env local, que está no .gitignore. Nunca commitar o .env no repositório.

Schemas¶

Schema Conteúdo Escrita
raw Dados brutos das fontes (CSV/Excel) Pipeline (ingestão Python)
staging Views limpas e padronizadas dbt
marts Dimensões, fatos e bridges dbt

Configurando o .env¶

DB_HOST=ep-xxx-xxx.sa-east-1.aws.neon.tech
DB_PORT=5432
DB_NAME=neondb
DB_USER=neondb_owner
DB_PASSWORD=senha_do_pipeline
DB_SSLMODE=require
DBT_TARGET=prod

O host do Neon segue o padrão ep-{nome}-{id}.{regiao}.aws.neon.tech. Você encontra na dashboard do Neon em Connection Details.

Rodando o pipeline¶

Com o .env apontando para o Neon:

# 1. Ingestão (carrega arquivos no schema raw)
./scripts/ingest.sh

# 2. Transformações dbt (cria staging views + marts tables)
./scripts/dbt-run.sh

# 3. Testes de qualidade
./scripts/dbt-test.sh

Os scripts de dbt leem DBT_TARGET do .env e passam --target prod automaticamente.

Ingestão incremental¶

Por padrão, a ingestão faz carga full: dropa cada tabela raw e recria do zero. Em produção, use o modo incremental para adicionar dados novos sem perder os existentes:

# Append sem dropar tabelas
./scripts/ingest.sh --mode incremental

# Apenas uma fonte
./scripts/ingest.sh --mode incremental sinan

Ou defina no .env para que incremental seja o padrão:

DEFAULT_LOAD_MODE=incremental

Quando usar cada modo em produção¶

Situação Modo Comando
Primeira carga no Neon full ./scripts/ingest.sh
Dados novos chegaram incremental ./scripts/ingest.sh --mode incremental
Dados fonte foram corrigidos full ./scripts/ingest.sh --mode full
Recriar tudo do zero full ./scripts/ingest.sh --mode full

Deduplicação

O modo incremental não deduplica na camada raw. Se rodar duas vezes com os mesmos arquivos, haverá duplicatas no raw. Isso é intencional: os modelos staging (dbt) tratam deduplicação com ROW_NUMBER(). Após ingestão incremental, rode ./scripts/dbt-run.sh para atualizar as views.

Acessando o banco¶

Via psql¶

# Usando o script (lê credenciais do .env)
./scripts/psql.sh

# Ou diretamente
psql "postgresql://neondb_owner:senha@ep-xxx.neon.tech/neondb?sslmode=require"

Queries úteis¶

-- Tabelas e contagem de linhas
SELECT schemaname, relname, n_live_tup
FROM pg_stat_user_tables
WHERE schemaname IN ('raw', 'staging', 'marts')
ORDER BY schemaname, n_live_tup DESC;

-- Verificar timestamp da última carga
SELECT _loaded_at, count(*)
FROM raw.sinan_notificacao
GROUP BY _loaded_at
ORDER BY _loaded_at DESC
LIMIT 5;

-- Tamanho do banco
SELECT pg_size_pretty(pg_database_size('neondb'));

Gerenciando usuários¶

Para criar um novo usuário de leitura (conecte como neondb_owner):

-- Criar usuário
CREATE ROLE nome_usuario WITH LOGIN PASSWORD 'senha_segura';

-- Conceder acesso de leitura
GRANT CONNECT ON DATABASE neondb TO nome_usuario;
GRANT USAGE ON SCHEMA raw, staging, marts TO nome_usuario;
GRANT SELECT ON ALL TABLES IN SCHEMA raw, staging, marts TO nome_usuario;

-- Auto-grant em tabelas futuras
ALTER DEFAULT PRIVILEGES IN SCHEMA raw GRANT SELECT ON TABLES TO nome_usuario;
ALTER DEFAULT PRIVILEGES IN SCHEMA staging GRANT SELECT ON TABLES TO nome_usuario;
ALTER DEFAULT PRIVILEGES IN SCHEMA marts GRANT SELECT ON TABLES TO nome_usuario;

Para revogar acesso:

REVOKE ALL PRIVILEGES ON ALL TABLES IN SCHEMA raw, staging, marts FROM nome_usuario;
REVOKE USAGE ON SCHEMA raw, staging, marts FROM nome_usuario;
REVOKE CONNECT ON DATABASE neondb FROM nome_usuario;
DROP ROLE nome_usuario;
